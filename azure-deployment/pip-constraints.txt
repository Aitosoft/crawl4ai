# Aitosoft: pip constraints for the production image build.
#
# Generated 2026-11-03 from `pip freeze` inside the image that was then in
# production, aitosoftacr.azurecr.io/crawl4ai-service:0.9.2-capacity-gate-2
# (built 2026-08-17), read with `az acr run`. The Dockerfile sets
# PIP_CONSTRAINT to this file, so every pip step resolves to the versions
# production already ran.
#
# Why: playwright, patchright, playwright-stealth and lxml are only lower-bounded
# in pyproject.toml, and `az acr build` resolves at build time. Without this, the
# v0.9.5 merge would ship with whatever was current on build day (playwright
# 1.62 -> 1.64+), and any rendering change after the deploy would be
# attributable to "upstream merge" or "new browser stack" with no way to tell
# (tasks/upgrade-upstream-v0.9.5.md §3.8). Moving the stack is then its own,
# later, attributable change: edit or regenerate this file deliberately.
#
# Not pinned, on purpose:
#   - crawl4ai itself (installed from the build context);
#   - anyio: deploy/docker/requirements.txt pins anyio==4.9.0 and a later
#     install step upgrades it (the 0.9.2 image has 4.14.2), so pinning either
#     value makes one step fail. It floats exactly as it did before;
#   - packages new since 0.9.2 (pypdf), which are not in the old freeze;
#   - Google Chrome: `playwright install chrome` takes current stable. The
#     0.9.2-capacity-gate-2 image ran Chrome 151.0.7922.137; record the new
#     image's version (AITOSOFT_CHANGES.md) rather than owning a .deb.
#
# Regenerate:
#   az acr run --registry aitosoftacr --cmd \
#     'aitosoftacr.azurecr.io/crawl4ai-service:<tag> pip freeze' /dev/null
# then drop crawl4ai and anyio.
